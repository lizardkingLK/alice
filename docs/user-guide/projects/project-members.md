# Project members

Control who can open a project's workspace and work on its items.

**Audience:** Managers and admins (project owners and admins)

---

## Why membership matters

Alice doesn't use a separate "private project" toggle. **Project membership**
decides who can:

- Open the project workspace (`/projects/[id]`)
- See the project in the **Projects** registry (for managers)
- Use project-scoped data in board, backlog, and forms

**Admins**, **owners**, and listed **members** can access projects they own or
belong to (membership-scoped). Everyone else is denied.

---

## Open the Members tab

1. Go to **Projects** and open a project.
2. Select the **Members** tab.

You'll see **Allocated members** and, if you have permission, an **Allocate
member** panel.

---

## Add a member

1. On **Members**, use **Allocate member** (right panel).
2. Search for a user by name or email.
3. Select them and choose **Add to Project**.

The person must already exist in the workspace (invited or self-registered).
Adding them here does **not** create a new Alice account — use
[Invite users](../users-and-access/invite-users.md) for that.

After they're added, the project appears in their project list (if they're a
manager) and they can work on that project's items.

---

## Remove a member

1. On **Members**, find the person in **Allocated members**.
2. Select the remove action (trash icon).

You **cannot** remove the **project owner** or the **project creator** (the
admin who created the project) from the list. Change the owner in project
settings first if ownership should move. Creator membership is locked by the
system.

---

## Who can add or remove members

**Managers** and **admins** see allocate/remove controls. Plain **members** on
a project can view the member list but can't change it.
